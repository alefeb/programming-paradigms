# Лабораторная работа №1

## Тема
Сравнение парадигм программирования на Python.

## Цель
Освоить основные способы организации программ и реализовать одну вычислительную задачу в императивном, процедурном, объектно-ориентированном и функциональном стилях Python.

## Индивидуальный вариант
Вариант №7: найти среднее значение чётных чисел.

## Результаты

Для исходного списка:
`[4, 7, 2, 9, 12, 5, 8, 3]`

Чётные числа:
`[4, 2, 12, 8]`

Среднее:
`6.5`

## Сравнение

| Критерий | Императивный | Процедурный | ООП | Функциональный |
|---|---|---|---|---|
| Основная единица | Команда | Функция | Объект | Преобразование |
| Изменяемое состояние | Много | Есть внутри функций | Есть внутри объекта/метода | Минимум |
| Декомпозиция | Минимальная | По функциям | По ответственности класса | По операциям |
| Расширяемость | Низкая | Средняя | Высокая | Высокая для коллекций |
| Объём кода | Средний | Средний | Большой | Минимальный |

## Вывод

Для простой задачи императивный стиль легче читать в начале обучения, потому что действия идут последовательно. Процедурный стиль удобен, когда алгоритм нужно разделить на отдельные подзадачи. ООП подходит для программы, где требуется хранить состояние и объединять данные с операциями. Функциональный стиль использует последовательность преобразований и уменьшает количество изменяемого состояния. Процедурный и функциональный варианты удобно тестировать по отдельным функциям и результатам преобразований. Для обработки коллекций функциональный подход хорошо подходит благодаря `filter()`, `map()` и генераторным выражениям.

## Ответы на контрольные вопросы

1. Парадигма программирования определяет способ организации программы и подход к решению задачи.
2. В императивной программе состояние изменяется через присваивания и изменение переменных, например `total += number ** 2`.
3. Процедурная декомпозиция разделяет решение на функции, каждая из которых выполняет отдельную подзадачу.
4. В ООП объектом является экземпляр класса `NumberCollection`.
5. Инкапсуляция проявляется в объединении данных и операций внутри класса. Атрибут `_numbers` хранит состояние объекта.
6. `filter()` отбирает элементы по условию, а `map()` преобразует каждый элемент.
7. Генераторное выражение задаёт преобразование коллекции без создания отдельного списка всех результатов.
8. Побочный эффект изменяет состояние за пределами результата функции, например вывод в консоль или изменение объекта.
9. Обработчик события выполняет действие в ответ на событие пользователя, например нажатие кнопки.
10. Несколько парадигм можно сочетать в одной программе.
11. Для небольших чистых функций проще проводить отдельные тесты, так как они имеют понятные входные данные и результат.
12. Для обработки коллекций удобен функциональный стиль, потому что операции отбора и преобразования выражаются через функции.
